# Evaluation Dataset

## Format

Each line is a JSON record (JSONL). Fields:

| Field | Type | Description |
|---|---|---|
| `case_id` | str | Unique stable ID for this example |
| `category` | str | `data_query`, `non_data_query`, `adversarial`, `ambiguous`, `stt_sensitive`, `boundary` |
| `subcategory` | str | Finer grouping within category |
| `input_text` | str | Ground-truth text representation of the spoken query |
| `expected_route` | str | `"tool"` or `"direct"` |
| `expected_tool` | str or null | Tool name if route=tool, else null |
| `expected_args` | dict | Expected tool arguments (may be partial/minimal) |
| `notes` | str | Human explanation of the case and its intent |

## Dataset Version

`dataset_version: v1`

## Available Datasets

- `voice_eval_v1.jsonl` — 30 cases covering CRM/support/analytics data queries, direct non-data questions, adversarial false-positive queries, ambiguous routing, STT-sensitive domain vocabulary, and boundary/limit cases.

## Extending the Dataset

1. Increment the version suffix (e.g. `voice_eval_v2.jsonl`).
2. Bump `dataset_version` in the file if using inline metadata.
3. All evaluation runs record which dataset was used, so historical results remain comparable.

## Ground-Truth Policy

Ground-truth `expected_route`, `expected_tool`, and `expected_args` are manually authored independently of the production routing implementation. They must NOT be generated by calling `_is_data_query()` or the LLM being evaluated.
